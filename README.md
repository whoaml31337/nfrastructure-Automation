# **Документация проекта: Система мониторинга на базе Prometheus, Grafana и Ansible**

---

## **1. Краткое описание проекта**
Этот проект представляет собой **автоматизированную систему мониторинга** серверов и приложений. Он позволяет:
- Собирать метрики работы серверов (CPU, RAM, диски) и приложений.
- Визуализировать данные в удобных дашбордах.
- Отправлять уведомления о проблемах (например, высокая загрузка CPU) в Telegram.
- Разворачивать всю инфраструктуру автоматически с помощью Ansible.

**Для кого это нужно:**
- Системным администраторам — для контроля серверов.
- Разработчикам — для мониторинга работы их приложений.
- DevOps-инженерам — как готовый шаблон для быстрого развёртывания.

---

## **2. Основные инструменты и их назначение**
| Инструмент          | Для чего нужен?                                                                                     | Почему выбран?                                                                 |
|---------------------|----------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------|
| **Prometheus**      | Собирает и хранит метрики с серверов и приложений.                                                 | Гибкость, популярность, мощный язык запросов (PromQL).                         |
| **Grafana**         | Визуализирует метрики в виде графиков и дашбордов.                                                 | Удобный интерфейс, поддержка Prometheus, множество готовых шаблонов.           |
| **Node Exporter**   | Собирает метрики сервера (CPU, RAM, диски).                                                        | Стандартный инструмент для мониторинга Linux-серверов.                         |
| **Alertmanager**    | Обрабатывает алерты из Prometheus и отправляет уведомления в Telegram/Slack.                       | Интеграция с Prometheus, поддержка группировки и фильтрации уведомлений.      |
| **Ansible**         | Автоматизирует установку и настройку всех компонентов.                                             | Простота использования, не требует агентов на серверах.                        |
| **Vagrant**         | Создает виртуальные машины для тестирования системы локально.                                      | Быстрое развертывание изолированной среды.                                     |

## **4. Подробное описание ролей Ansible**

### **Роль: `prometheus`**
**Назначение**: Установка и настройка Prometheus для сбора метрик.  
**Ключевые файлы**:
- `tasks/main.yml` — устанавливает Prometheus и копирует конфиг.
- `templates/prometheus.yml.j2` — настраивает, откуда собирать метрики (Node Exporter, Flask).

**Пример конфига**:
```yaml
scrape_configs:
  - job_name: 'node-exporter'  # Сбор метрик сервера
    static_configs:
      - targets: ['192.168.56.10:9100']  # Адрес Node Exporter
```

---

### **Роль: `node_exporter`**
**Назначение**: Сбор метрик сервера (CPU, RAM, диски).  
**Как работает**:
1. Устанавливает Node Exporter.
2. Открывает порт `9100` для Prometheus.


---

### **Роль: `grafana`**
**Назначение**: Визуализация метрик в дашбордах.  
**Что делает**:
1. Устанавливает Grafana.
2. Настраивает источник данных (Prometheus).
3. Импортирует готовый дашборд из `files/flask-dashboard.json`.

**Доступ**:
- Веб-интерфейс: `http://<сервер>:3000` (логин: `admin/admin`).

---

### **Роль: `alertmanager`**
**Назначение**: Отправка уведомлений о проблемах.  
**Пример уведомления в Telegram**:
```
[FIRING] HighCPUUsage
CPU usage > 80% on server1
```
**Настройка**:
- Токен бота и chat_id хранятся в зашифрованном виде (Ansible Vault).

---

### **Роль: `app`**
**Назначение**: Развертывание тестового Flask-приложения с метриками.  
**Пример метрики**:
```python
from prometheus_client import Counter
REQUEST_COUNT = Counter('http_requests_total', 'Total HTTP Requests')
```

---

## **5. Как взаимодействуют компоненты?**

1. **Node Exporter** и **Flask** отправляют метрики в **Prometheus**.
2. **Prometheus** проверяет правила алертов и передаёт их в **Alertmanager**.
3. **Alertmanager** отправляет уведомления в **Telegram**.
4. **Grafana** берёт данные из **Prometheus** и показывает их в дашбордах.

## **6. Почему именно эти инструменты?**
| Альтернатива       | Почему не выбрана?                                                                 |
|--------------------|-----------------------------------------------------------------------------------|
| **Zabbix**         | Сложнее в настройке, менее гибкий для cloud-решений.                              |
| **Telegraf**       | Не интегрируется напрямую с Alertmanager.                                         |
| **Nagios**         | Устаревшая архитектура, слабая поддержка метрик.                                  |
| **Datadog**        | Платный для масштабирования.                                                      |

## **7. Как развернуть систему?**
1. **Запустите виртуальные машины**:
   ```bash
   vagrant up
   ```
2. **Разверните мониторинг**:
   ```bash
   ansible-playbook -i ansible/inventory.ini ansible/playbooks/playbook.yml
   ```
3. **Откройте Grafana**:  
   `http://localhost:3000`

## **8. Частые вопросы**
**Q: Как добавить новый сервер в мониторинг?**  
A: Добавьте его IP в `inventory.ini` и запустите playbook.

**Q: Где хранятся секреты (Telegram токен)?**  
A: В файле `group_vars/monitoring.yml`, но я рекомендую хранить в зашифрованном виде.

**Q: Как изменить порты?**  
A: Отредактируйте `Vagrantfile` и конфиги ролей.
